# ufifeed

Личные сводки из каналов и групп Telegram, выбранных в папке отдельного аккаунта.

Читающий аккаунт собирает сообщения через MTProto. Отдельный бот присылает сводки **в личный чат вашего основного аккаунта** и принимает настройки только от него. Основной аккаунт не обязан состоять во всех источниках, но для открытия ссылок на приватные сообщения ему нужен доступ к соответствующим чатам.

## Что работает

- Выбор папки читающего аккаунта: `/folders`, `/folder ID`; автоматическая сверка состава каждые 5 минут и перед сводкой.
- Текст и подписи к медиа, новые сообщения и правки, дочитывание истории после перезапуска. Начальный импорт — последние 24 часа.
- Подборки по ключевым словам, исключения, удаление точных текстовых повторов, ссылки на оригиналы.
- Опциональные AI-сводки через OpenAI-compatible Chat Completions endpoint с проверкой ссылок и отдельным AI-доступом для каждого источника.
- Расписание в часовом поясе Seattle (`America/Los_Angeles`), ручная сводка, пауза и возобновление. Время выбирается в боте; по умолчанию расписание выключено.
- SQLite, зашифрованные тексты сообщений и очередь доставки, сохранение прогресса и обработка неизвестного результата отправки.
- Docker Compose, тесты и GitHub Actions. Один контейнер, открывать входящие порты не нужно.

Поддерживаются папки с явно выбранными каналами и группами, включая закреплённые. Личные диалоги и боты пропускаются. Категории «все каналы/группы» и фильтры unread/muted/archived пока не поддерживаются. Защищённый и исчезающий контент не сохраняется; медиафайлы не скачиваются. Удаления обрабатываются по доступным событиям и не гарантируются Telegram для всех случаев.

## Запуск на VM

Код и image готовятся скриптом из чистого закоммиченного дерева:

```sh
./scripts/deploy.sh
```

Цель: `ufian@192.168.1.99`, отдельный проект `ufifeed`, releases по Git SHA и постоянные данные в `/home/ufian/ufifeed/state`. Первый деплой собирает образ и ожидает авторизации. Последующие обновляют уже запущенный сервис; остановленный сервис остаётся остановленным.

Однократная настройка в вашем терминале:

```sh
ssh -t ufian@192.168.1.99 'cd /home/ufian/ufifeed/current && docker compose run --rm app setup'
ssh -t ufian@192.168.1.99 'cd /home/ufian/ufifeed/current && docker compose run --rm app auth'
ssh ufian@192.168.1.99 'cd /home/ufian/ufifeed/current && docker compose up -d app'
```

`setup` попросит `api_id`/`api_hash` из [my.telegram.org](https://my.telegram.org) и токен **нового выделенного бота** от [BotFather](https://t.me/BotFather). Затем покажет одноразовую команду: отправьте её боту с основного аккаунта, чтобы привязать владельца. Секреты вводятся скрыто и сохраняются только на VM. `auth` попросит телефон, код входа и при необходимости пароль 2FA **читающего аккаунта**. Не присылайте эти данные в чат разработки.

Если код для `auth` не приходит, проверьте служебный чат Telegram **в читающем аккаунте** на уже вошедшем устройстве. Команда показывает способ доставки, выбранный Telegram; SMS не гарантируется. Не повторяйте запросы подряд. Отменить ожидание можно `Ctrl+C`.

Можно войти без кода через QR:

```sh
ssh -t ufian@192.168.1.99 'cd /home/ufian/ufifeed/current && docker compose run --rm app auth --qr'
```

На телефоне переключитесь в **читающий аккаунт** → **Настройки → Устройства → Подключить устройство**, сканируйте QR в терминале и подтвердите вход. QR обновляется при истечении срока, при включённой 2FA терминал попросит пароль скрытым вводом. Перед повтором завершите предыдущую команду `auth`; `Ctrl+Z` приостанавливает команду, а не завершает её. Не публикуйте QR или коды входа.

После запуска откройте бота с основного аккаунта:

```text
/start
/folders
/folder 2
/sources
/topics релиз, обновление, безопасность
/exclude #реклама, промокод
/schedule 09:00,20:00 America/Los_Angeles
/digest
/status
```

ID папки, темы и время здесь — примеры. Папку создавайте и пополняйте в Telegram читающего аккаунта. Список чатов на сервере вручную редактировать не нужно. Время и настройки, изменённые в боте, сохраняются в БД и не сбрасываются при обновлении image.

## AI-режим

В `state/config/ufifeed.toml` включите `[ai].enabled`, задайте `base_url` и `model`; API key запишите в `state/secrets/credentials.json` полем `ai_api_key`. Для локального endpoint ключ может не требоваться. Перезапустите `docker compose up -d --force-recreate app`. Credentials провайдера не принимаются командами бота.

Затем в боте включите конкретные источники и режим:

```text
/ai_source -1001234567890 on
/mode ai
```

По умолчанию AI выключен; вновь добавленные/возвращённые источники получают AI: off. Есть ограничение числа запросов в сутки UTC и объёма входа; это не денежный лимит провайдера. Ошибка AI не подменяется незаметно обычной подборкой: материал остаётся в БД, ошибка видна в `/status`, автоматическое окно не продвигается.

[Условия Telegram](https://telegram.org/tos/content-licensing#large-language-models-and-ai) ограничивают использование данных для AI шире обучения. Не предполагается, что личное использование или локальная модель автоматически дают разрешение; для AI-источников нужно установить подходящее основание обработки. Детали — в [исследовании](docs/research.md).

## Разработка и проверки

Python 3.12–3.14, рекомендуемый runtime — 3.13. Зависимости зафиксированы в `uv.lock`.

```sh
uv sync --frozen --python 3.13
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run ufifeed --config config/ufifeed.example.toml check
```

Для локального запуска создайте `data/` и `secrets/`, выполните `uv run ufifeed setup`, `uv run ufifeed auth`, `uv run ufifeed run`. Не запускайте локальный и серверный экземпляры с одним bot token или session. Для Docker на другой машине используйте UID/GID 1000 и доступные ему каталоги `config/`, `data/`, `secrets/`.

## Эксплуатация

- Все команды: `/help`. `/pause` останавливает плановые сводки, сбор продолжается.
- `/retry ID` объясняет повтор доставки с неизвестным исходом; подтверждённый повтор может создать дубль. Автоматического повтора такого запроса нет.
- `/purge ID` удаляет сохранённые сообщения отключённого источника и тексты сводок. Сначала уберите источник из папки и дождитесь сверки. Уже доставленные сообщения бота и внешние backup эта команда не удаляет.
- По умолчанию тексты хранятся 30 дней. Читаемые метаданные (ID, названия, времена, настройки) в SQLite не зашифрованы; тексты сообщений и outbox зашифрованы Fernet. Файл session и credentials защищены правами доступа, а не Fernet.
- Не теряйте `state/secrets/data.key`: без него восстановить тексты БД невозможно. Ключ и session не должны попадать в Git/image/логи.
