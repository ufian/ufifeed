# ufifeed

Личный сервис, который следит за выбранными каналами и чатами Telegram и присылает через бота подборки важного в заданное время.

## Статус

Исследование и проектирование, 25 ноября 2026. Приложение пока не реализовано и на VM не развёрнуто.

Основной сценарий: **чужие каналы и чаты, куда нельзя добавить своего бота**. Поэтому читать сообщения должен Telegram-клиент под пользовательским аккаунтом, а отправлять сводки — отдельный бот.

## Предлагаемое решение

- Python, Telethon для чтения по MTProto, aiogram для Bot API.
- Один процесс с асинхронными задачами сбора, расписания и отправки; Docker Compose на `ufian@192.168.1.99`.
- SQLite на постоянном локальном volume: сообщения, позиции чтения, расписания, подготовленные сводки и очередь доставки.
- Сначала текст и подписи к медиа, подборки по темам и правилам с обязательными ссылками. LLM — отдельный режим после проверки условий использования конкретных источников.
- Управление через личный чат с ботом, доступ только владельцу. Веб-интерфейс для MVP не требуется.

Бот сам по себе не получает доступ к произвольным чужим каналам: см. [официальные ограничения Bot API](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

Для AI есть существенное ограничение: [текущие условия Telegram](https://telegram.org/tos/content-licensing) распространяются шире обучения моделей. Нельзя считать любую LLM-сводку чужих сообщений разрешённой только потому, что модель не обучается на этих данных. Подробности и границы вывода — в исследовании.

## Что понадобится для запуска

1. `api_id` и `api_hash` своего приложения из [my.telegram.org](https://my.telegram.org), аккаунт с доступом к источникам, однократная авторизация кодом и, при наличии, паролем 2FA.
2. Бот от [BotFather](https://t.me/BotFather), его токен и личный чат для доставки.
3. Список источников, темы интереса, время сводок и часовой пояс.
4. Для LLM-режима — отдельно определённое основание обработки источников и выбранный провайдер или локальная модель.

Токены, коды входа, файлы сессии и содержимое приватных чатов не должны попадать в Git. Ввод авторизации планируется интерактивно на VM, без передачи кодов в чат разработки.
